# 简介

Protocol Buffers 是 Google 开发的一种数据序列化格式。与 XML 和 JSON 相比，它更小、更快、更简单。它非常适合用于数据存储、RPC（远程过程调用）通信以及跨语言数据交换。

**主要优势：**

- **高效：** 序列化后的数据体积小，解析速度快。

- **强类型：** 通过 `.proto` 文件明确定义数据结构。

- **跨语言：** 支持 C\+\+, Java, Python, Go, C\# 等多种语言。

# 解析数据（以Hbase 为例）

1. 安装三方库：

Protobuf解析数据需依赖`.proto` 文件，故在解析数据前需根据`proto` 文件生成对应的 \*pb2\.py文件

2. 找到或下载对应的`.proto` 文件

注意：数据流与对应的proto文件强相关，故需确认解析的数据流对应的proto文件是否正确。

以Hbase为例，Hbase对应的proto文件与Hbase版本相关，故需下载对应Hbase版本的对应模块的proto文件

下载对应版本对应数据流的proto文件，以Hbase2\.4\.16为例：

- Replication\.proto（数据流对应类型）：https://github\.com/apache/hbase/blob/rel/2\.4\.16/hbase\-protocol\-shaded/src/main/protobuf/Replication\.proto 

- HBase\.proto（Replication依赖proto文件） ：https://github\.com/apache/hbase/blob/rel/2\.4\.16/hbase\-protocol\-shaded/src/main/protobuf/HBase\.proto



3. 生成\*pb2\.py文件

```Bash
python -m grpc_tools.protoc -I<搜索路径> --python_out=<输出路径> --grpc_python_out=<输出路径> <你的.proto文件>

**-I<路径>** (或 --proto_path): 指定 .proto 文件的搜索路径。如果不确定，通常设为当前目录 .。
**--python_out=<路径>**: 指定生成的消息序列化代码（*_pb2.py）的输出目录。
**--grpc_python_out=<路径>**: 指定生成的 gRPC 服务存根代码（*_pb2_grpc.py）的输出目录。
**<你的.proto文件>**: 需要编译的源文件路径。

python -m grpc_tools.protoc -I./protoc --python_out=./pb2 --grpc_python_out=./pb2 ./protoc/HBase.proto ./protoc/Replication.proto 
```

**HBase\_pb2\.py： 仅用于解码**

**HBase\_pb2\_grpc\.py： 进行操作，需依赖pb2\.py**

4. 使用\*pb2\.py模块解析数据

```Python
import Replication_pb2  # 步骤3生成的py模块
# 该py模块是手动生成出来的，需注意存放文件，考虑系统导入时能否找到
# 若proto文件存在依赖，其依赖的proto野心生成对应的pb2模块，且需能被当前pb2识别

raw = b'\n2target-node1,target-node2,target-node3:2181:/hbase8\x00@\x01X\x00'
peer = Replication_pb2.ReplicationPeer()
peer.ParseFromString(raw)
print(peer)
"""
clusterkey: "target-node1,target-node2,target-node3:2181:/hbase"
bandwidth: 0
replicate_all: true
serial: false
"""
```



5. 注意

pb2模块只能解析标准的Protobuf 数据，以Hbase为例，通过kazoo获取的数据并非标准的Protobuf 数据，而是拼接了Hbase头文件的数据，直接进行解析时会报错。

```Python
import Replication_pb2
from kazoo.client import KazooClient
from kazoo.exceptions import NoNodeError, KazooException

zk = KazooClient(hosts="172.16.46.112")
zk.start(timeout=10)
raw, _ = zk.get("/hbase/replication/peers/1")
# raw: b'\xff\x00\x00\x00\x14master:16000C\x0bn\xccf\xf0\xff\xa7PBUF\n2target-node1,target-node2,target-node3:2181:/hbase8\x00@\x01X\x0

# raw 对应的数据是 replication 下的 peers 故需注册Replication_pb2.ReplicationPeer()
peer = Replication_pb2.ReplicationPeer() 
# 若直接转义raw：
 peer.ParseFromString(peer_blob)
"""
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
google.protobuf.message.DecodeError: Error parsing message with type 'hbase.pb.ReplicationPeer'
"""
```

原因：

raw中b'\\xff\\x00\\x00\\x00\\x14master:16000C\\x0bn\\xccf\\xf0\\xff\\xa7PBUF'并非标准的Protobuf 数据
raw 数据，可以发现数据由三部分组成：
    **头部**：\\xff\\x00\\x00\\x00\\x14master:16000\.\.\.（包含魔数和 ServerName 信息）
    **分隔符**：PBUF
    **实际 Protobuf 数据**：\\n2target\-node1\.\.\.

正确解析应当切去头部和分隔符，仅保留Protobuf 进行解析

```Python
import Replication_pb2
from kazoo.client import KazooClient
from kazoo.exceptions import NoNodeError, KazooException

zk = KazooClient(hosts="172.16.46.112")
zk.start(timeout=10)
raw, _ = zk.get("/hbase/replication/peers/1")
# raw: b'\xff\x00\x00\x00\x14master:16000C\x0bn\xccf\xf0\xff\xa7PBUF\n2target-node1,target-node2,target-node3:2181:/hbase8\x00@\x01X\x0

separator = b'PBUF'
idx = raw.find(separator)
pb_data = raw[idx + len(separator):]
# pb_data：b'\n2target-node1,target-node2,target-node3:2181:/hbase8\x00@\x01X\x00'

peer.ParseFromString(pb_data)
print(peer)
"""
clusterkey: "target-node1,target-node2,target-node3:2181:/hbase"
bandwidth: 0
replicate_all: true
serial: false
"""
print(peer.clusterkey)
"""
'target-node1,target-node2,target-node3:2181:/hbase'
"""
```
