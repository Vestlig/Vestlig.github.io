# 一、简介  

RabbitMQ 是一个开源消息代理软件，基于 AMQP（高级消息队列协议）实现，用于异步通信、系统解耦、流量削峰等场景。  

核心功能：  

- 消息的生产、存储、路由和消费  

- 支持多种消息模式（点对点、发布/订阅、RPC等）  

- 高可用性（通过集群和镜像队列）  

- 丰富的插件生态（如 MQTT、STOMP 支持）

# 二、安装与配置  

## 安装步骤  

- Ubuntu/CentOS：  

    ```Plain Text
    # 安装 Erlang（RabbitMQ 依赖）
    sudo apt-get install erlang  # Ubuntu 
    sudo yum install erlang      # CentOS 
    
    # 安装 RabbitMQ 
    sudo apt-get install rabbitmq-server  # Ubuntu 
    sudo yum install rabbitmq-server      # CentOS 
    ```



- Windows：从官网下载安装包，默认启用管理插件（访问 `http://localhost:15672`）。  



- Docker：  

    ```Plain Text
    docker run -d --name rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:3-management 
    ```



## 基础配置  

- 启动服务：`systemctl start rabbitmq-server`  

- 启用管理界面：`rabbitmq-plugins enable rabbitmq_management`  

- 创建用户：  

    ```Plain Text
    rabbitmqctl add_user admin your_password 
    rabbitmqctl set_user_tags admin administrator 
    ```

# 三、核心概念与组件  

1. Producer：消息生产者，发送消息到 Exchange。  

2. Exchange：接收消息并路由到队列，类型包括：  

    - Direct（精准匹配 Routing Key）  

    - Topic（通配符匹配，如 `*.error`）  

    - Fanout（广播到所有绑定队列）  

    - Headers（基于消息头匹配）  

3. Queue：存储消息的缓冲区。  

4. Binding：定义 Exchange 和 Queue 的关联规则。  

5. Consumer：消息消费者，从队列获取消息。

# 四、基础使用示例（Python \+ pika库）  

## 发送消息  

```Plain Text
import pika 
 
connection = pika.BlockingConnection(pika.ConnectionParameters('localhost'))
channel = connection.channel()
 
声明 Exchange 和 Queue，并绑定 
channel.exchange_declare(exchange='logs', exchange_type='fanout')
channel.queue_declare(queue='log_queue')
channel.queue_bind(exchange='logs', queue='log_queue')
 
发布消息 
channel.basic_publish(exchange='logs', routing_key='', body='Hello RabbitMQ!')
connection.close()
```



## 消费消息  

```Plain Text
def callback(ch, method, properties, body):
    print(f"Received: {body}")
 
channel.basic_consume(queue='log_queue', on_message_callback=callback, auto_ack=True)
channel.start_consuming()
```

# 五、高级特性  

## 消息持久化  

- 队列持久化：`channel.queue_declare(queue='log_queue', durable=True)`  

- 消息持久化：`properties=pika.BasicProperties(delivery_mode=2)`  



## 消息确认（ACK）  

- 手动 ACK：关闭 `auto_ack`，消费完成后调用 `ch.basic_ack(delivery_tag=method.delivery_tag)`。  

- NACK：拒绝消息并重新入队。  



## 死信队列（DLX）  

配置队列的 `x-dead-letter-exchange` 参数，处理无法消费的消息。  



## 集群部署  

- 节点加入集群：  

    ```Plain Text
    rabbitmqctl stop_app 
    rabbitmqctl join_cluster rabbit@node1 
    rabbitmqctl start_app 
    ```

# 六、最佳实践与注意事项  

1. 连接管理：复用 TCP 连接，避免频繁创建/销毁。  

2. 队列设计：  

    - 避免无限增长（设置 TTL 或最大长度）。  

    - 优先使用 Topic Exchange 实现灵活路由。  

3. 错误处理：  

    - 实现重试机制和死信队列。  

    - 监控消息积压（通过管理界面或 Prometheus 插件）。  

4. 安全性：  

    - 使用 SSL/TLS 加密通信。  

    - 限制默认用户权限。

# 七、常见问题  

1. 消息丢失：确保消息和队列持久化，并启用 ACK 机制。  

2. 消息顺序性：单消费者保证顺序，多消费者可能乱序。  

3. 重复消费：消费者需实现幂等性处理。  

4. 性能瓶颈：横向扩展集群节点，优化网络和磁盘 I/O。
